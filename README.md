# Практична робота №9 — Варіант 1

> **Завдання:** Дослідити ситуацію, коли користувач може змінити файл, хоча не є його власником. Навести можливі сценарії та протестувати їх.

---

## Компіляція та запуск

```bash
gcc -Wall -Wextra -O0 file_perms.c -o file_perms
./file_perms
```

---

## Сценарії

### 1. Файл `0600` — тільки власник
```
-rw-------  user group  file
```
Інший користувач не може ні читати, ні писати. `open()` → `-1`, `errno = EACCES`.

### 2. Файл `0664` — group-write
```
-rw-rw-r--  user group  file
```
Будь-який член тієї ж групи може **писати**, навіть не будучи власником.

```bash
# Перевірити групи поточного користувача
id
groups

# Додати користувача до групи (root)
usermod -aG groupname username
```

### 3. Файл `0666` — world-write
```
-rw-rw-rw-  user group  file
```
**Будь-який** користувач системи може читати і писати. Небезпечна конфігурація.

### 4. Sticky bit на директорії (`01777`)
```
drwxrwxrwt  /tmp
-rw-rw-rw-  file_in_tmp
```
- **Запис** у файл `0666` — дозволено будь-кому
- **Видалення** файлу — лише власник або root

```bash
ls -ld /tmp        # побачити sticky bit (t)
chmod +t /mydir    # встановити sticky bit
```

### 5. ACL (розширені списки доступу)
Дозволяє надати доступ **конкретному користувачеві** незалежно від `chmod`:

```bash
# Дати alice права rw на файл, навіть якщо вона не власник і не в групі
setfacl -m u:alice:rw secret.txt
getfacl secret.txt

# Перевірити, чи підтримується ACL
mount | grep acl
```

### 6. Користувач root
Root ігнорує **всі** права доступу UNIX (крім `--x` для виконання).

## Таблиця підсумку

| Сценарій | Читання | Запис | Видалення |
|---|---|---|---|
| `0600`, не власник | ❌ | ❌ | ❌ |
| `0664`, член групи | ✅ | ✅ | ❌* |
| `0666`, будь-хто | ✅ | ✅ | ❌* |
| Sticky dir + `0666` | ✅ | ✅ | ❌ (тільки власник) |
| ACL `u:user:rw` | ✅ | ✅ | ❌* |
| root | ✅ | ✅ | ✅ |

*Видалення залежить від прав на **директорію** (потрібен `w` на директорію).

## Корисні команди

```bash
# Переглянути права файлу
ls -l file.txt
stat file.txt

# Змінити права
chmod 664 file.txt      # власник rw, група rw, інші r
chmod o+w file.txt      # додати world-write

# Перевірити доступ без відкриття файлу
access("file.txt", W_OK)   # у C

# ACL
setfacl -m u:bob:rw file.txt
getfacl file.txt
setfacl -b file.txt         # видалити всі ACL
```

---

## Важливо для безпеки

- Файли з `0666` або `0777` — потенційна вразливість (будь-хто може модифікувати)
- `/tmp` використовує sticky bit саме для захисту від видалення чужих файлів
- ACL не видно у звичайному `ls -l` (тільки `+` в кінці прав) — потрібен `getfacl`
- `umask` визначає **маску** прав при створенні файлів (за замовчуванням `022`)
