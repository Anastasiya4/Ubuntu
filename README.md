#  Практична робота №4 — Варіант 1

> **Завдання:** Реалізувати власний `malloc`/`free` на базі `brk()` для малих блоків і `mmap()` для великих. Підтримати розбиття та об'єднання вільних блоків. Показати вплив фрагментації.

---

## Архітектура

### Стратегія виділення

| Розмір блоку | Метод | Системний виклик |
|---|---|---|
| < 128 КБ | Керований список (heap) | `sbrk()` / `brk()` |
| ≥ 128 КБ | Пряме відображення | `mmap(MAP_ANONYMOUS)` |

### Структура заголовка блоку

```
+------------------+---------------------+
|   block_hdr_t    |    дані (size байт)  |
|  size / free /   |                      |
|  is_mmap / ptrs  |                      |
+------------------+---------------------+
       HDR_SIZE           size байт
```

Кожен brk-блок зберігає `size`, прапорець `free`, посилання `next`/`prev` для двозв'язного списку.

---

## Алгоритми

### Пошук вільного блоку — First Fit
Проходимо список з початку, повертаємо перший блок з `free == 1` і `size >= потрібного`.

### Розбиття блоку (split)
Якщо знайдений вільний блок більший за потрібне + `HDR_SIZE + ALIGN`, залишок відокремлюється в новий вільний блок.

```
До:    [  вільний 512 байт  ]
Запит: 64 байти

Після: [ зайнятий 64 байт ][ вільний 432 байт ]
```

### Об'єднання блоків (coalesce)
При `my_free()` перевіряємо сусідів: якщо `next->free` або `prev->free` — зливаємо блоки в один більший.

```
До:    [ зайнятий ][ ВІЛЬНИЙ ][ ВІЛЬНИЙ ][ зайнятий ]
Після: [ зайнятий ][    ВІЛЬНИЙ (злитий)  ][ зайнятий ]
```

---

## Компіляція та запуск

```bash
gcc -Wall -Wextra -O0 mymalloc.c -o mymalloc
./mymalloc
```

> `-O0` — щоб компілятор не оптимізував виклики malloc/free.

## Очікуваний вивід

```
Розмір заголовка блоку : 40 байт
Поріг mmap             : 131072 байт

=== Демонстрація фрагментації ===

-- Крок 1: виділяємо 5 блоків --
  [malloc] brk     64 байт  @ 0x...
  [malloc] brk    128 байт  @ 0x...
  [malloc] brk     64 байт  @ 0x...
  [malloc] brk    256 байт  @ 0x...
  [malloc] brk     64 байт  @ 0x...

--- Стан купи ---
  [ 0] addr=0x...  size=    64  зайнятий
  [ 1] addr=0x...  size=   128  зайнятий
  ...

-- Крок 2: звільняємо b та d --
  [free]   mark   128 байт  @ 0x...
  [free]   mark   256 байт  @ 0x...

-- Крок 3: запит 300 байт --
  [!] Фрагментація! Неможливо задовольнити запит 300 байт,
      хоча сумарно вільно більше.

-- Крок 4: звільняємо a, c, e → coalescing --
  [free]   mark    64 байт  @ 0x...
  ...
```

---

## Демонстрація фрагментації

```
Виділено:  [a:64][b:128][c:64][d:256][e:64]
Звільнено b,d:  [a:64][FREE:128][c:64][FREE:256][e:64]
Запит 300 байт → FAIL (128 < 300 і 256 < 300, хоча разом 384 > 300)
```

Це класична **зовнішня фрагментація** — сумарно пам'яті вистачає, але немає суцільного блоку потрібного розміру.

## Порівняння з glibc malloc

| Властивість | Наша реалізація | glibc malloc |
|---|---|---|
| Поріг mmap | 128 КБ (фіксований) | 128 КБ (динамічний) |
| Алгоритм пошуку | First Fit | Best Fit + bins |
| Потокобезпечність | Ні | Так (arena) |
| Coalescing | Так (базовий) | Так (розширений) |
| Захист від переповнення | Ні | Canary (у деяких збірках) |
