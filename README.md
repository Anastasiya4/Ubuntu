# Практична робота №8 — Варіант 1

> **Завдання:** Дослідити поведінку `write()` при записі у FIFO, коли читачів немає, і пояснити результат.

---

## Теорія: що таке FIFO

FIFO (named pipe) — спеціальний файл у файловій системі, який забезпечує однонаправлену передачу даних між процесами. На відміну від звичайного pipe, має ім'я у файловій системі (`mkfifo`).

```
Процес A (write) ──→ [ FIFO /tmp/test ] ──→ Процес B (read)
```

---

## Поведінка при відсутності читача

| Ситуація | Результат |
|---|---|
| `open(O_WRONLY)` без читача (блокуючий) | `open()` **блокується** до появи читача |
| `open(O_WRONLY\|O_NONBLOCK)` без читача | `open()` → `-1`, `errno = ENXIO` |
| `write()` після зникнення читача | Ядро надсилає **SIGPIPE** процесу |
| SIGPIPE не перехоплено | Процес **завершується** |
| SIGPIPE перехоплено або `SIG_IGN` | `write()` → `-1`, `errno = EPIPE` |

## Очікуваний вивід

```
=== Демонстрація 1: SIGPIPE при записі без читача ===
  open(O_WRONLY|O_NONBLOCK) → помилка: No such device or address
  Причина: FIFO не можна відкрити на запис без читача

=== Демонстрація 2: читач є, потім закриває кінець ===
  [читач] прочитано 32 байт
  [записувач] 1-й write → 32 байт
  [записувач] 2-й write → -1, errno = Broken pipe
  [!] Отримано SIGPIPE — читач закрив кінець!

=== Демонстрація 3: SIGPIPE ігнорується (SIG_IGN) ===
  write() → -1, errno = 32 (Broken pipe)
  (SIGPIPE ігноровано — write повертає -1/EPIPE замість краші)

=== Демонстрація 4: атомарність write() — PIPE_BUF ===
  PIPE_BUF на цій системі = 4096 байт
  Записи <= PIPE_BUF є атомарними
  Записи >  PIPE_BUF можуть бути розбиті ядром
```

---

## Схема демонстрацій

```
Demo 1: відкриття без читача
  Writer ──→ open(O_NONBLOCK) ──→ ENXIO (негайно)

Demo 2: читач зникає
  Reader ──→ open() ──→ read() ──→ close()
  Writer ──→ open() ──→ write(32B) ✓ ──→ write(4096B) → SIGPIPE

Demo 3: SIG_IGN
  Writer ──→ write() ──→ -1/EPIPE (без краші процесу)
```

---

## Висновки

1. `write()` у FIFO без читача → ядро надсилає **SIGPIPE** процесу-записувачу.
2. За замовчуванням SIGPIPE **завершує процес** (подібно до `kill -13`).
3. При `signal(SIGPIPE, SIG_IGN)` або власному обробнику → `write()` повертає `-1`, `errno = EPIPE`.
4. `open(O_WRONLY|O_NONBLOCK)` без читача → одразу `-1`, `errno = ENXIO`.
5. Записи ≤ `PIPE_BUF` (4096 байт на Linux) **атомарні** — не перемішуються між процесами.

---

## Корисні команди

```bash
# Створити FIFO вручну
mkfifo /tmp/myfifo

# Записати у FIFO (заблокується без читача)
echo "hello" > /tmp/myfifo

# Читати з FIFO в іншому терміналі
cat /tmp/myfifo

# Переглянути сигнали процесу
kill -l | grep PIPE
```
