# Практична робота 14 (Timers) — Варіант 1

> **Завдання:** Змінити програму з прикладу POSIX interval timers так, щоб вона оновлювала системний лічильник у змінній (рахувала тики).

---

## Компіляція та запуск

```bash
gcc -Wall -Wextra -O0 -lrt timer_counter.c -o timer_counter

./timer_counter            # тік кожну секунду, Ctrl+C для зупинки
./timer_counter 2          # тік кожні 2 секунди
./timer_counter 1 10       # тік кожну секунду, зупинка після 10 тіків
```

Всього тіків : 10

## Що змінено відносно оригінального прикладу

| Оригінал | Завдання 1 |
|---|---|
| Виводив лише `"Tick\n"` | Виводить `"Тік #N"` з номером |
| Не рахував тіки | `volatile sig_atomic_t tick_count` |
| Нескінченний цикл | Зупинка після N тіків (аргумент) |
| `CLOCK_REALTIME` | `CLOCK_MONOTONIC` (стабільніший) |
| Немає `timer_gettime()` | Виводить стан таймера на старті |
| Немає `timer_delete()` | Коректне знищення таймера |

## Ключові деталі реалізації

### `volatile sig_atomic_t` для лічильника
```c
static volatile sig_atomic_t tick_count = 0;
```
- `volatile` — забороняє компілятору кешувати значення в регістрі
- `sig_atomic_t` — гарантує атомарне читання/запис для типу

### Чому `write()` замість `printf()` в обробнику?
`printf()` не є async-signal-safe — може бути перервана в невизначеному стані. `write()` — системний виклик, гарантовано безпечний.

### `CLOCK_MONOTONIC` vs `CLOCK_REALTIME`
```
CLOCK_REALTIME  — може стрибати при зміні системного часу (ntp, date)
CLOCK_MONOTONIC — завжди зростає, не залежить від системного часу
```
Для таймерів із точним інтервалом завжди краще `CLOCK_MONOTONIC`.

### Зупинка таймера через `timer_settime` з нульовими значеннями
```c
struct itimerspec its = {0};   /* it_value = {0,0} */
timer_settime(tid, 0, &its, NULL);  /* вимикає таймер */
```
