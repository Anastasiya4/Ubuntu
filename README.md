# Практична робота №7 — Варіант 1

> **Завдання:** Написати програму, яка визначає структуру ієрархії директорій для поточного користувача, починаючи з кореня, виключаючи циклічні посилання, але зберігаючи символьні.

---

## Опис

Програма рекурсивно обходить дерево директорій від заданої точки (за замовчуванням — домашня директорія користувача). Виводить дерево у стилі утиліти `tree`.

### Ключові властивості

| Властивість | Реалізація |
|---|---|
| Виключення циклів | Таблиця відвіданих `(dev, inode)` — унікальний ідентифікатор файлу |
| Збереження симлінків | `lstat()` замість `stat()` — симлінк відображається як `name -> target` |
| Алфавітний порядок | `qsort()` по іменах перед рекурсією |
| Права доступу | `opendir()` відкидає недоступні директорії з повідомленням |

---

## Чому `(dev, inode)`, а не шлях?

```
/home/user/loop -> /home/user   ← симлінк на батька

Якщо відстежувати шляхи:
  /home/user/loop/loop/loop/... → нескінченність

Якщо відстежувати inode:
  /home/user        inode=12345
  /home/user/loop   lstat → симлінк, не заходимо
  Але stat(loop) → inode=12345 → вже бачили → [цикл]
```

## Компіляція та запуск

```bash
gcc -Wall -Wextra -O2 dirtree.c -o dirtree
```

### Варіанти запуску

```bash
./dirtree              # домашня директорія поточного користувача
./dirtree /home        # задана директорія
./dirtree /etc         # системні конфіги
./dirtree .            # поточна директорія
```

## Алгоритм виявлення циклів

```
walk(path):
  st = lstat(path)

  якщо симлінк:
    вивести "name -> target"
    якщо веде до директорії і inode вже бачили → "[цикл]"
    повернутись  ← не заходимо всередину

  якщо не директорія → пропустити

  якщо (st.dev, st.ino) у таблиці visited → "[цикл]"
  додати (st.dev, st.ino) до visited

  для кожного запису в директорії (sorted):
    walk(child)

  видалити (st.dev, st.ino) з visited  ← дозволяє повторний візит
                                           через різні шляхи
```

> Видалення inode після повернення з рекурсії дозволяє відвідати одну директорію через **різні шляхи**, але запобігає **нескінченному циклу** по тому самому шляху.

## Порівняння з утилітою `tree`

```bash
# Стандартна утиліта (тільки директорії)
tree -d /home/user

# Наша програма
./dirtree /home/user
```

| Функція | `tree -d` | `dirtree` |
|---|---|---|
| Дерево директорій | Так | Так |
| Символьні посилання | Так | Так |
| Виявлення циклів | Так | Так (через inode) |
| Без зовнішніх залежностей | Ні (`tree` потрібен) | Так |
| Доступ до `/proc` | Не потрібен | Не потрібен |
