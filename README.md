# Лабораторна робота №2 — Варіант 1

> **Завдання:** Напишіть програму, що визначає максимально можливий розмір сегмента купи.

---

## Опис

Програма послідовно виділяє блоки пам'яті по **16 МБ** через `malloc`, поки система не відмовить у виділенні (повертає `NULL`). Кожен блок заповнюється байтом `0xAB` за допомогою `memset`, щоб:

- операційна система реально виділила фізичні сторінки (а не лише зарезервувала адресний простір);
- компілятор не оптимізував виклики як «мертвий код».

Після вимірювання вся виділена пам'ять звільняється через `free`.

---

## Компіляція та запуск

```bash
gcc -Wall -Wextra -O2 heap_max.c -o heap_max
./heap_max
```

## Пояснення сегментів пам'яті

| Сегмент | Вміст | Зберігається у файлі? |
|---------|-------|-----------------------|
| **text** | Машинний код (інструкції) | Так |
| **data** | Ініціалізовані глобальні/статичні змінні | Так |
| **BSS** | Неініціалізовані глобальні/статичні змінні | Ні (лише розмір) |
| **heap** | Динамічна пам'ять (`malloc`/`free`) | Ні (runtime) |
| **stack** | Локальні змінні, адреси повернення | Ні (runtime) |

Купа (heap) розташована між сегментом BSS та стеком у віртуальному адресному просторі процесу. Зростає **вгору** (до вищих адрес), тоді як стек зростає **вниз**.

## Аналіз розмірів сегментів

Після компіляції перевірити розміри сегментів:

```bash
# Розміри сегментів
size heap_max

# Символи у виконуваному файлі
nm heap_max

# Детальна інформація про секції ELF
objdump -h heap_max

# Залежні бібліотеки
ldd heap_max
```

### Вплив прапорців компіляції на розмір файлу

| Прапорець | Ефект |
|-----------|-------|
| без прапорців | базовий розмір |
| `-g` | збільшує розмір файлу (налагоджувальна інформація) |
| `-O2` | зменшує text-сегмент (оптимізація коду) |
| `-O3` | мінімальний text, агресивна оптимізація |
| `-Os` | оптимізація розміру файлу |

```bash
# Порівняння розмірів
gcc heap_max.c -o heap_no_opt && size heap_no_opt
gcc -g heap_max.c -o heap_dbg  && size heap_dbg
gcc -O2 heap_max.c -o heap_O2  && size heap_O2
gcc -O3 heap_max.c -o heap_O3  && size heap_O3
```

## Примітки

- На системах з **overcommit** (`/proc/sys/vm/overcommit_memory = 1`) `malloc` може повертати ненульовий вказівник навіть коли реальної пам'яті немає — `memset` змушує ОС реально виділити сторінки.
- Щоб перевірити поточне значення: `cat /proc/sys/vm/overcommit_memory`
- Обсяг доступної пам'яті: `free -h`
