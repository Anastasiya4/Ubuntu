#  Практична робота №3 — Варіант 1

> **Завдання:** Написати програму, яка створює багато потоків та перевірити вплив `ulimit -u`.

---

## Опис

Програма послідовно створює POSIX-потоки (`pthread_create`) до тих пір, поки система не відмовить у створенні нового потоку (помилка `EAGAIN`). Це відбувається при досягненні ліміту `ulimit -u` (`RLIMIT_NPROC`) — максимальної кількості процесів/потоків для користувача.

Кожен поток викликає `sleep(60)`, щоб утримувати ресурс відкритим протягом усього тесту. Після завершення вимірювання всі потоки коректно скасовуються через `pthread_cancel`.

---

## Компіляція та запуск

```bash
gcc -Wall -Wextra -O2 -pthread thread_limit.c -o thread_limit
```

### Запуск без обмеження
```bash
./thread_limit
```

### Запуск з обмеженням (Docker / bash)
```bash
# Встановити м'який ліміт на 100 потоків/процесів
ulimit -u 100
./thread_limit
```

### У Docker-контейнері
```bash
docker run --ulimit nproc=100:100 -v $(pwd):/app gcc \
    bash -c "cd /app && gcc -pthread thread_limit.c -o thread_limit && ./thread_limit"
```

## Очікуваний вивід

### Без обмеження
```
ulimit -u : необмежено
Починаємо створювати потоки...
  Створено потоків: 50
  Створено потоків: 100
  ...

=== Результат ===
Успішно створено потоків : 3842
Завершення потоків...
Готово.
```

### З обмеженням `ulimit -u 100`
```
ulimit -u : 100 потоків/процесів
Починаємо створювати потоки...
  Створено потоків: 50

[!] pthread_create повернула EAGAIN після 87 потоків.
    Причина: досягнуто ліміту ulimit -u або RLIMIT_NPROC.

=== Результат ===
Успішно створено потоків : 87
Ліміт ulimit -u          : 100
Завершення потоків...
Готово.
```

> Кількість менша за ліміт (87 < 100), бо певна кількість потоків вже зайнята самим bash та системними процесами користувача.

## Корисні команди для дослідження

```bash
# Переглянути поточні ліміти
ulimit -a

# М'який та жорсткий ліміт окремо
ulimit -Su    # soft
ulimit -Hu    # hard

# Переглянути потоки процесу під час виконання
watch -n1 "ps -eLf | grep thread_limit | wc -l"

# Переглянути RLIMIT_NPROC через /proc
cat /proc/self/limits | grep processes

# Встановити ліміт через setrlimit у shell-скрипті
prlimit --nproc=50 ./thread_limit
```

---

## Пояснення

| Поняття | Опис |
|---------|------|
| `ulimit -u` | Максимальна кількість процесів **і потоків** для одного користувача |
| `RLIMIT_NPROC` | Відповідний системний ресурс (`sys/resource.h`) |
| `EAGAIN` | Помилка `pthread_create` при вичерпанні ліміту |
| м'який ліміт | Поточне обмеження, яке процес може збільшити до жорсткого |
| жорсткий ліміт | Абсолютна межа, яку може змінити лише `root` |

---

## Примітки щодо Docker

У Docker `ulimit -u` встановлюється прапорцем `--ulimit nproc=M:H` (soft:hard). За замовчуванням у контейнері ліміт успадковується від хосту. Для ізольованого тесту завжди задавайте явно:

```bash
docker run --ulimit nproc=200:200 ubuntu ./thread_limit
```
